## What Juno Is Doing

Creating specification documents from the signal trends received from tickets via various channels as Slack, Jira, feedback emails

## Four Levers

**Stop Conditions** (Loop):

Create at max 5 specs a week, and each should be broken down into user stories that the developers can work on.

**Structured Tool Outputs** (Tools):

Create 1 high level specs document and then create user stories with a structure of "I as a <type of user> ",  " I want to <task> ", so that " it <value it brings or brings in efficiency". These should be emailed directly to me and not sent to the developers directly

**Confidence Thresholds** (Verification):

Create specs design documents, to when the confidence is high and value and efficiency to the user is high

**North Star** (Context):

Create a specifications library for all trending signals received and send a full list at the end of every week

## Rules of Engagement

**Agency Permission:**

Can draft spec documents, only send directly to me

**Access Control:**

Access signals across all channels (read-only access) - no write permissions given

**Fallback Protocols:**

Send an email to me when the agent running fails

**Checkpoints:**

Mid of every week, send what has been specked out already
